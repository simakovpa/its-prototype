# Прототип модуля ИТС — «Шаблон расчёта»

Демонстрационное React-приложение (Vite + Ant Design 5), реализующее рекурсивный
движок расчёта индекса технического состояния по решениям из
`its_module_architecture_decisions.md` (включая раздел 13 — стресс-тест архитектуры).

## Запуск

```bash
npm install
npm run dev
```

## Публикация на GitHub Pages

```bash
npm run deploy   # соберёт dist/ и скопирует в docs/ (кросс-платформенно, через Node)
git add docs -f
git commit -m "Update prototype"
git push
```

В Settings → Pages репозитория: источник — Deploy from branch, ветка `master`, папка `/docs`.

## Что реализовано

### Ядро
- Рекурсивный движок (`src/engine/`) — одна сущность «Узел методики»
  (`container` / `leaf` / `dynamicGroup` / `libraryRef`), работает на любом уровне.
- Каталог стратегий свёртки: MIN, простое среднее, взвешенная сумма, взвешенный
  дефицит-индекс, взвешивание по показателю приведения, условная свёртка по доле
  «плохих» элементов (без возможности сослаться сама на себя как на ветку А/Б).
- Три источника данных параметра, два типа шкал, три способа сопоставления,
  конфигурируемое поведение при отсутствии факта.
- Материализация узлов (виртуальный/материализованный), правила коррекции на
  любом нелистовом уровне.

### Версионирование методик
- Черновик + история неизменяемых версий, публикация замораживает снимок,
  разрешает ссылки библиотеки в конкретное содержимое, проверяет сумму весов
  (предупреждение, не блокировка).
- «Дублировать методику» — параллельные методики с независимой историей версий,
  не дублирует связанные методики оборудования (в отличие от копирования узла).
- Архивирование методик и записей библиотеки вместо физического удаления.

### Решения стресс-теста (`src/utils/graphOps.js` и др.)
- Проверка циклических связей — и между методиками (динамические группы), и
  внутри библиотеки (ссылки), единым механизмом обхода графа.
- Транзитивное распространение индикатора «Требуется пересчёт» через связанные
  методики после публикации версии (уведомление в интерфейсе).
- Правило коррекции видит критических потомков независимо от того, исключены ли
  они из свёртки из-за отсутствия данных.
- Копирование узла с динамической группой внутри дублирует связанную методику —
  копия по-настоящему независима.
- Библиотека поддерживает вставку копией или живой ссылкой (заморозка — на
  публикации версии методики); ссылочные узлы визуально выделены (тег «библиотека»).
- Отсутствие показателя приведения исключает экземпляр из свёртки с
  перенормировкой — не подставляется произвольный вес.
- Каждое правило коррекции проверяется против исходного результата; при
  нескольких сработавших — действует последнее.

### Библиотека и расчёт
- Экран «Библиотека» — создание типовых узлов/шкал с нуля или сохранение из
  методики; независимая копия по умолчанию, опция «вставить как ссылку».
- Пробный расчёт (по черновику или любой версии) и официальный (требует
  опубликованной версии, пишется в историю с привязкой к паре методика+версия).
- Явная подсказка в интерфейсе: версии связанного через динамические группы
  оборудования в расчёте объекта всегда действующие, без переопределения.

## Моковые данные (`src/data/`)

Одна подстанция, два трансформатора (Т-1 — старый, с двумя открытыми дефектами;
Т-2 — новый, исправный), у каждого — свой Ввод, протоколы измерений, справочники
(номенклатура, типы дефектов, измеряемые параметры).

## Сознательно упрощено / отложено

Роли и права доступа, модуль «Аналитика», полные технологические цепочки для
ТП/ВЛ, точный перечень статусов дефекта, автоматический сброс Фо при демонтаже —
см. раздел «Известные ограничения» архитектурного документа.
